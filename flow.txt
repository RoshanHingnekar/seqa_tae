1. WHAT IS THIS PROJECT? (OVERVIEW & PURPOSE)
================================================================================
QAEstimator Pro is an enterprise software testing resource and person-hour
estimation platform designed for Quality Assurance (QA) Managers, SDET Leads,
and Engineering Directors.

Key Problems It Solves:
-----------------------
- Software development teams often guess QA timelines, leading to testing
  delays, missed bugs, or team burnout.
- QAEstimator Pro replaces guesswork with a calibrated mathematical engine that
  takes concrete project variables (Lines of Code, Number of Test Cases,
  Coverage Target, System Complexity, and Testing Environments) and computes:
    * Total QA Person-Hours
    * Person-Days (based on an 8-hour workday)
    * Person-Weeks (based on a 5-day workweek)
    * Recommended QA Team Composition (QA Lead, Manual Engineers, SDETs)
    * Workload Distribution (Manual Testing, Automation, Retesting, Planning, Reporting)
- Includes full Test Management, Team Roster & Capacity tracking, Audit History,
  and Instant Export to formal PDF and Excel reports.

2. TECHNICAL ARCHITECTURE & HOW IT WORKS UNDER THE HOOD
================================================================================
The project follows a modern decoupled client-server architecture:

A. FRONTEND CLIENT (/client):
   - Framework: React 18 + TypeScript + Vite 6
   - Styling: Tailwind CSS (Clean Enterprise Blue #2563EB theme)
   - Icons: Lucide React
   - Visual Analytics: Recharts (Interactive Line charts, Donut charts, Area charts)
   - Document Export: jsPDF + jspdf-autotable (PDF) + SheetJS / xlsx (Excel spreadsheets)
   - Port: http://localhost:5173
   - Reverse Proxy: Vite proxies all `/api/*` traffic seamlessly to http://localhost:5000

B. BACKEND API SERVER (/server):
   - Runtime: Node.js (tested with v24 and modern LTS versions) + TypeScript + tsx
   - Framework: Express 4
   - ORM / Database Layer: Prisma ORM v5
   - Primary Database: SQLite (file: server/prisma/dev.db) - zero setup required
   - Security: JWT (JSON Web Tokens) with Bearer token authentication + Bcrypt password hashing
   - Input Validation: Zod schemas for type-safe payload validation
   - Port: http://localhost:5000

C. DATABASE SCHEMA ENTITIES:
   - User: Accounts, credentials, roles, profile, organization
   - Project: Software projects with code volume (LOC), test cases, coverage, status
   - Estimation: Detailed calculation records with multipliers and breakdowns
   - TestCase: Test cases (ID, Title, Module, Priority P1-P3, Type, Status, Assignee)
   - TeamMember: QA engineers, skills, availability (Available/Busy/On Leave), capacity (%)
   - Report: Stored generated estimation and test audit reports
   - EstimationHistory: Historical snapshots of calculations for sprint audit trail
   - Notification: In-app user notifications and alerts
   - SystemSetting: Configurable baseline rates and multipliers

3. CORE ESTIMATION ENGINE & MATHEMATICAL FORMULA
================================================================================
The estimation engine computes QA effort using four deterministic components:

Formula:
--------------------------------------------------------------------------------
1. LOC Effort:
   LOC Effort = (LOC / 1,000) * LOC_RATE
   (Default LOC_RATE = 6.4 person-hours per 1,000 lines of code)

2. Test Case Effort:
   Test Case Effort = TestCases * TEST_CASE_RATE
   (Default TEST_CASE_RATE = 0.1242 person-hours per test scenario (~7.5 minutes))

3. Base Effort:
   Base Effort = LOC Effort + Test Case Effort

4. Coverage Multiplier:
   Coverage Multiplier = 1 + ((TargetCoverage - 70) / 100)
   (Baseline is 70% coverage. 85% coverage yields 1.15x multiplier)

5. Complexity Multiplier:
   - Low Complexity:    0.85x
   - Medium Complexity: 1.00x
   - High Complexity:   1.25x

6. Environment Multiplier:
   - 1 Environment:  1.00x
   - 2 Environments: 1.10x
   - 3 Environments: 1.20x

7. Total Person-Hours:
   Total Hours = Base Effort * CoverageMultiplier * ComplexityMultiplier * EnvMultiplier

8. Sizing Conversions:
   - Person-Days  = Total Hours / 8.0
   - Person-Weeks = Person-Days / 5.0

Effort Distribution Breakdown:
------------------------------
- Manual Functional Testing: ~42% of total hours
- Automation Suite Dev & Run: ~28% of total hours
- Defect Retesting & Verification: ~15% of total hours
- Test Planning & Environment Setup: ~10% of total hours
- Test Reporting & Sign-off: ~5% of total hours
